# 答案正确性与忠实度：待冻结的评价协议

状态：**协议草案，未开始评分**。它补的是 proposal 中尚未测量的两个结果，不替代 E29/E39 的引用 F1。不得把写好协议记为实验完成。

## 可以复用什么

E29 的 600 题两臂回答、题目、`answer_short`、官方证据和候选引用都已保存。评价这些回答不需要重新生成；若使用 API judge，只有评审调用需要新预算。人工评审则不需要 API。对 E39 只能等其回答生成后按同一协议评价。

## 评价单位与指标

- **正确性**：回答是否给出题目所要求的正确事实、数量、比较或推理结论。逐题记 1（完整正确）、0（不正确或没有回答）。部分正确另作标签，主指标仍按预先冻结规则评分；不能评分时记录原因，不能当成正确，也不能静默删掉。
- **忠实度**：回答中影响结论的事实性主张是否被它实际引用的证据支持。逐题记 1（全部有支持）、0（至少一条重要主张无支持）。引用编号相同不是支持证据；要检查文字、图表内容及数字。没有给出实质答案的拒答单列，避免靠全拒答获得高忠实度。
- **引用 F1**：继续独立报告官方引用抽取口径，不与以上指标混成一个总分。

主分析按文档分组、配对计算“改进臂 − 基线臂”的正确率差和忠实度率差。使用文档 bootstrap 的 ratio-of-sums 估计，报告题数、文档数、待裁决数及 95% CI；两个主比较作为一个事先固定的 Holm 族。不要按看到的结果改主要指标。

## 盲评流程

1. 在评分前冻结样本、题目顺序、两臂输入/回答哈希及协议。优先评价全部 600 题；若只能评一部分，先在文档层抽样并登记抽样规则，禁止按输赢挑题。E29 子集早已被观察，应继续标为探索性评价。
2. 对每题随机打乱 A/B 显示顺序，不显示算法名、历史 F1 或路由收益。保留独立映射表，在评分锁定后揭盲。评审员只看问题、回答、参考答案与能支持裁决的原文/图片。
3. 正确性先独立于引用检查；忠实度再对照实际被引用内容。遇到参考答案疑似错误、图像无法读取、引用不能定位时，标记待裁决并写原因，不凭猜测评分。
4. 两名评审员独立评分。先用独立校准样本磨合规则，校准题不进入正式结果；正式分歧保留原始两份判断，再做裁决。报告裁决前一致率和分歧类型，不只给裁决后的平均分。
5. 若用模型评审，冻结模型、版本、prompt 和生成配置，禁止同时让生成臂知道评审规则后重写回答。保留原始评审输出，并用人工子样本检验评审误差；不能把单个模型的未校验判断当作无误 gold。

## 效率另测

在同一机器上固定并记录候选池、预计算范围与批量策略，分别记录 CPU 检索、GPU 检索、路由预测和生成的时间。预热与冷启动分开，报告重复次数、中位数和尾延迟。已缓存 ColQwen 排名上的离线回放时间不能冒充实际 GPU 调用耗时。生成 token 分模型报告，费用只按已核实的模型价格和账单换算。

这份草案还需要在正式评分前确定可接受的样本量、评分执行者与预算；当前没有任何正确性/忠实度提升或非劣结论。
