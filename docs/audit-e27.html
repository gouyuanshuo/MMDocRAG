本报告发布后自查发现的一处错误，已撤回。 初版曾声称 E24 的结论「方向是错的」，依据是在视觉槽位上单独替换后， ColQwen 在 k=15（+0.0269）与 k=20（+0.0220）上显著优于图片描述检索。 该结论只在 396 题的探索性测试半区成立。 在全部 2,000 题上重算，同一比较为 +0.0075 / +0.0089 / +0.0039（k=10/15/20）， 三个预算的置信区间全部跨 0；且在放开配额的配置搜索中， 最好的 ColQwen 配置（0.8114）排不进前七，全部被 RRF-打描述 的配置压住（最优 0.8197）。

因此 E24 的原结论成立：在本项目可获得的池规模与裁剪粒度下，ColQwen 不值它的 GPU 成本。 我先前的「反转」本身就是一个低功效切分上的假阳性——正是本次审计要防的那类错误， 却在审计报告里犯了一次。如实记录，不予掩饰。 仍然成立的部分：E24 原记录写的 「每篇中位 29 个图片候选」（superseded）是按题加权的口径； 按文档计中位 20、均值 29.76，@20 对 111/220 篇（50.5%）等于取走整个池，饱和描述应当加强。

本次审计自身的一个失误，如实记录。我在 audit_e19_ties.py 中构造的 「closest-to-fixed oracle」指标是退化的：它在每题的并列最优集合内取最靠近固定策略者， 而该集合内任一元素都达到最大值，故它恒等于 oracle，差值恒为 0，不携带任何信息。 该指标已从结论中剔除，改用「固定策略本身已是最优的题目占比」。

数据集共 14,826 张图片，其中属于这 220 篇评测文档的有 13,999 张， 而两个池在 evaluation 范围内只含 6,487 张不同图片——7,512 张（53.66%）文档内图片从未进入任何池。（6,504 是全库 223 篇文档的 distinct img_path，与 13,999 不同口径，不可相除。） 因此 self-built 也不是完整多模态语料，两个池共用同一个不完整图片侧， 不能称为「两次独立复现」，应称为 两种池构造的敏感性分析，且该分析只覆盖文本侧差异。

能否建立完整图片池

  • 对 ColQwen（像素）可以：需为 13,999 张图片建索引，按 E24 实测吞吐约为当前 6,565 张的 2.1 倍工作量，单卡可行。
  • 对 BM25 / BGE（描述）不可以：这两个检索器读的是 VLM 撰写的 img_description， 而缺失的 7,512 张图片没有任何描述。补齐需要为它们生成描述，属 API 支出，且生成模型与官方描述不同源会引入新的混淆。
  • 因此完整图片池上的比较只能在视觉检索器之间做；描述类检索器无法在完整池上公平参与。这一约束必须写进报告，不能回避。

七 · 测试集反复使用

该切分自 E9 起被反复观察，并用于选择方法（配额、检索器、融合方式、粒度）。 因此它不再是干净的确认集，本报告全部结果标记为 exploratory。 拟采用的确认方案，二选一：

  1. document-grouped nested CV：外层按文档分 5 折，内层在训练折上选配额与融合超参， 外层折上评测，报告折间均值与文档聚类 CI。全部离线、零 API，可立即执行。
  2. 冻结后外部确认：把 D/G 配置连同全部超参冻结成一个配置文件， 在 MMLongBench-Doc（proposal §9 已列为第二数据集）上跑一次，不做任何调参。

方案 1 成本更低且不引入跨数据集混淆，建议先做方案 1，方案 2 作为可选加强。

八 · 其他实验记录的修正

E19 · 并列最优导致 oracle 空间被高估

C.argmax(axis=1) 在并列时返回最小索引。实测：

指标（k=20）自建池canonical
有 >1 个最优配额的题97.2%97.0%
并列最优个数中位数（共 21 个）1616
固定配额本身已是最优的题79.5%78.2%
argmax 落在 a=0 的题1,013 / 1,999918 / 2,000
oracle − 固定（真实 regret）+0.0694+0.0744
E19 所报 oracle − 排列对照+0.1728+0.1787
并列感知排列对照后+0.1166+0.1219

审计估计的 +0.069~+0.074 与本次复算逐位一致。 argmax 把一半以上的题判为 a=0（全图片），而在每题并列集合内均匀取样时分布近乎平坦—— 偏置来源确认。今后 E19 应报 regret（+0.069/+0.074）作为自适应分配的上界， 并同时报「79% 的题固定策略已最优」，而不是把 +0.173/+0.179 称作 query-specific structure。

E17 · 训练的标签不是 retriever outcome

确认：clf.fit(..., mostly_visual[tr]) 训练的是gold 模态标签， 随后 np.where(pred_vis, bm[te], dn[te]) 把「视觉→BM25、文字→dense」写死。 该实验因此只否证了一条人工指定的策略，并未否证「逐题选择检索器」本身。 「61.9% 是 Both」也不足以推出结构上无可选：BM25 与 BGE 都同时检索文本与图片描述， 模态构成与检索器优劣不是同一件事。须重做：直接以逐题 recall(dense) − recall(bm25) 为回归/分类目标，与静态 RRF 及 E27 的 D/G 比较。

E9 · 13 维结果当前不可复现

确认：load_features 恒为 hstack([emb(384), shallow(13)]) = 397 维， 没有任何 CLI 可选择特征子集。记录簿中「13 维下 2/19 显著提升、4/19 显著下降」 无法由当前代码复现，须撤下直至补齐。此外 13 维浅层特征包含人工标注的 question_type，属部署时未必可得的 privileged feature， 重做时须拆为 deployable / privileged / embedding / candidate-shape 四组分别报告并写 manifest。

E18 · 结论须收窄

实测 quote_ocr 6,565 条中 1,270 条（19.3%）为空 （审计所称 1,279 与此接近，差异应为统计口径）。 非空也不等于 OCR 完整准确。因此只能表述为： 在当前问题条件化池、BM25 与 RapidOCR 表示下，VLM 描述显著优于裁剪 OCR； 不能推出差距源于「视觉理解而非提取失败」。 另，把 recall 差值（+0.42）与 router 的 F1 差值相除得出「60 倍」是跨指标比较，无效，须删除。

E24 · 结论方向须反转

池规模确认且比原记录更严重：按文档计图片候选中位数仅 20（均值 29.76，最小 1、最大 262；此处此前误写为 29.4）。按问题加权则是中位 29、均值 34.92——同一个池的两个不同统计量，报告时必须说明是哪一个。全部由 python experiments.py verify E24 断言。 而评测到 k=20——对一半文档而言 @20 等于取走整个图片池，饱和是结构性的。 模型亦为 ColQwen2-v1.0 而非论文的 v0.1、文本侧为 bge-small 而非 bge-large。 更重要的是，按修正口径在视觉槽位上单独替换后，ColQwen 相对图片描述检索 在 k=15 与 k=20 上显著更好（+0.0269、+0.0220）。 E24 原结论成立的范围仅限于「在 E24 那套 quote 级图片池与 @20 饱和条件下未观察到优势」， 而「不值 GPU 成本」这一判断已被本次复算推翻。

E25 / E26 · 预算单位与覆盖范围

确认 n_tok = len(tokenize(t))，其中 tokenize 是正则词元 [a-z0-9]+(?:[.\-][a-z0-9]+)*，不是生成模型的 BPE token。 全文「固定 token 预算」须改为 word-like retrieval budget， 或用最终生成模型的 tokenizer 重算（后者更好，因为 proposal §13 的成本论证依赖真实计费 token）。 此外该实验仅覆盖 text gold + BM25 + 字符切分，未覆盖视觉 region/page、 parent section、稠密检索与下游生成，不能宣称 RQ3 已完成，应改为「RQ3 的文本-BM25 切片已完成」。

十 · 拟采用的表述

建议以下述文字替换记录簿 E27 与 proposal 第 18 节的对应段落。已按本次多重比较结果比审计建议再收窄一档：

在两种候选池构造变体与一个 document-disjoint 的探索性切分上， 模态内 BM25–BGE-small RRF 融合配合固定均衡配额，相对本地 BGE-small-only 替代基线 将 Recall@k 提高约 0.023–0.046（document-cluster bootstrap，95% CI 均不含 0）。 相对最接近论文的本地 hybrid 对照（BGE-small 文本 + ColQwen2-v1.0 视觉 + 官方配额）， 稳健显著的提升集中在紧预算 k=10，约 0.036–0.037；k=15 与 k=20 的差异不可与 0 区分。 在对 54 次比较作 Bonferroni 校正后，仅「RRF 文本 + ColQwen 视觉 + 均衡配额」相对该对照 在 k=10 上于两个池同时存活（+0.047 / +0.046）。

同时必须明确写出：

  • E27 是一个 static retrieval baseline，不是 adaptive routing；
  • 本项目的 adaptive 方法此后必须在相同预算与相同候选池上超过 E27（具体为 D 与 G），而不是超过 A；
  • 停止使用「击败论文配置」「两个池独立复现」「六格全部显著」三种表述；
  • 图片侧检索一律称 image-description retrieval，仅 ColQwen 臂称 visual retrieval；
  • 所有结论标注 exploratory，直至完成 document-grouped nested CV 或外部确认集。

这个修正让项目的叙事更清楚，而不是更弱。 E27 变成一个诚实的强静态基线：融合与均衡配额在紧预算下确有收益， 而视觉检索器在宽预算下确有收益（E24 的方向修正）。 于是 adaptive 部分的任务被重新定义为「能否超过这个强静态基线」—— 即使最终超不过，「强静态融合有效、简单逐题路由不稳定」本身就是完整的研究结论， 而且现在它建立在正确的基线、正确的分母和正确的抽样单位上。

补充 · document-grouped nested CV（审计后新增）

审计第七项要求的确认协议已实现（retrieval/nested_cv.py）： 外层按文档分 5 折，内层只看其余文档、在 5 种检索器配置 × 全部 k+1 种配额上选配置，held-out 折用一个它从未影响过的配置评分。 每道题最终都被 out-of-fold 评分，因此可用全部 2,000 题而非 396 题，功效约提升 2.2 倍。

同上（canonical 池） +0.0541 [+0.0402,+0.0689] *+0.0269 [+0.0170,+0.0367] *
